# Error codes and i18n (translations)

This directory holds centralized error definitions and a small i18n system for the frontend.

- **`src/`** – Go packages per module (`sys`, `auth`, `asset`, `system`). Each file defines `var ErrXxx = errx.XXX("CODE", ...)`.
- **`langs/`** – Generated JSON files per language (`en.json`, `zh.json`, `fr.json`) for the frontend. Generated by `cmd/gen_langs/`.
- **`cmd/gen_langs/`** – Scans `src/**/*.go`, parses the translation block in `/* ... */` comments, and writes `langs/<lang>.json`.
- **`cmd/add_templates/`** – Adds missing i18n comment blocks to files in `src/`.

Identity is the login center (auth + asset + system). Do not add leftover IAM domains (`tenants`, `access`, `directory`).

---

## How to write the translation block (`/* ... */`)

Each error **code** (e.g. `"ACCOUNT_NOT_FOUND"`) must have a corresponding **translation block** in a block comment at the **bottom** of the same `.go` file.

### Format

1. Use a **single** block comment: `/* ... */`.
2. For each code, add:
   - One line: **`!CODE_STRING`** (the exact code value, no quotes).
   - One or more lines: **`*<lang><text>`** where `<lang>` is a language code (e.g. `en`, `zh`, `fr`) and `<text>` is the message inside `<` and `>`.

### Rules

- **`!CODE`** – Must match the string passed to `errx.*(...)` in the same file. One line per code.
- **`*lang<message>`** – Language line. `lang` is 2+ lowercase letters; the message is everything between `<` and `>`.
- Blank lines between entries are allowed.
- The block is usually placed at the **end of the file** after `var (...)`.

### Example

```go
var (
	ErrAccountNotFound = errx.NotFound("ACCOUNT_NOT_FOUND", "account not found")
)

/*
!ACCOUNT_NOT_FOUND
*en<account not found>
*zh<账号不存在>
*fr<compte introuvable>
*/
```

### Notes

- **Order**: List each `!CODE` once; all its `*lang<...>` lines must follow before the next `!CODE`.
- **Generation**: Run `task errors` (or `task errors:gen-langs`). It scans all `src/**/*.go` and merges every block into `langs/en.json`, `langs/zh.json`, etc.
- **Production copy**: `task errors:gen-langs:prod` applies `*p*lang<...>` overrides.
- **New codes**: When you add `ErrXxx = errx.XXX("NEW_CODE", ...)`, add a matching `!NEW_CODE` and at least `*en<...>` in the same file’s block comment.
- HTTP responses return English `err_code` + `message`. Frontend looks up `err_code` in `langs/*.json`.
